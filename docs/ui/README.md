# Базовый UI расследования: план реализации

## Основание и границы

Источник: `docs/AI_Powered_Observability_Hackathon_1.pdf`, номера на слайдах 7, 8, 10, 12, 15, 16.
Must have всей системы: один датасет Loghub, шаблоны, один класс аномалий, evidence timeline, ранжированные гипотезы первопричины.
Definition of Done: воспроизводимость, ссылки на доказательства, сравнение с baseline, ограничения, следующий шаг.
UI показывает результаты этих процессов, но сам не заменяет ingestion, детектор или backend ранжирования.

Текущий код: `src/ui/components/incident-workspace.tsx` содержит shell, chat и статичный checkout-экран; произвольные MCP actions пока не загружают записи. Цвета и типографику сохраняем. Убираем фиктивные live-метрики и необоснованные проценты уверенности.

Этот этап реализует базовые компоненты, их типизированный контракт и сквозной локальный UI-сценарий. Фикстура OpenStack-inspired синтетическая, НЕ результат обработки Loghub. Реальный data adapter, production detector и оценка precision@k не входят в эти три UI-задания. Не считать весь хакатон завершённым после их выполнения.

## Общие требования ко всем исполнителям

- Прочитать AGENTS.md и актуальные Next.js guides в `src/ui/node_modules/next/dist/docs/` перед кодом: server/client components и CSS. Для hooks нужна client boundary.
- Все данные через props/контракт. Никаких запросов в ClickHouse из браузера, секретов, новых зависимостей или генерации JSX моделью.
- Существующий API чата и `UiAction` не менять. Текст UI английский, как в исходниках; требования и отчёты могут быть русскими.
- Использовать существующие CSS variables и Lucide; локальные CSS modules для новых панелей. Нативные доступные элементы, видимый focus, labels, перенос длинных строк, адаптация к 375/768/1440px.
- Доказательство всегда имеет стабильный ID и источник; неизвестный ID не открывает другую запись. Синтетический пример не становится Live из-за доступности MCP.
- Данные логов рендерить как текст, не HTML. Не выводить скрытые секреты. `redacted` явно показывать.
- Не менять backend, Docker, Go/Python, lockfile, окружение или чужие файлы. Не коммитить. Сохранять параллельные изменения коллег.
- Проверки: `npm run typecheck` из `src/ui`; координатор запускает общую сборку и браузерную проверку. Промежуточные missing imports соседнего незавершённого задания не исправлять заглушками.

## Приёмочный сценарий

1. Без API-ключа открыть демо напрямую, не отправляя запрос LLM.
2. Увидеть synthetic/source/time/coverage, класс аномалии и основание срабатывания.
3. Из первой гипотезы открыть конкретное доказательство: выделяется правильная строка и раскрываются raw/fields/source.
4. Переключиться в timeline, увидеть хронологию и основание корреляции без утверждения причинности.
5. Из шаблона перейти к его событиям; искать/фильтровать; пустой результат отличать от ошибки загрузки.
6. В карточке следующего шага увидеть проверку, ожидаемый результат и ограничения; нет кнопок реального исправления.
7. Вернуться к предыдущему виду; неизвестная ссылка показывает unavailable и не подставляет демо.
8. На мобильном нет горизонтального переполнения страницы; элементы доступны с клавиатуры.

## Статус

Все три задания реализованы агентами `gpt-5.6-terra / medium` и прошли независимую проверку координатора. Результаты и ограничения: [VERIFICATION.md](VERIFICATION.md).

Во время реализации в рабочем дереве параллельно появились `LiveLogExplorer`, `/api/logs`, ClickHouse client и изменения Docker/env. Они сохранены и не приписываются этим трём исполнителям. Теперь sidebar Log explorer открывает реальный обозреватель; для проверки нашей панели используйте «Open synthetic demo» → ссылку на evidence → вкладки Timeline / Logs / Patterns. Live `show_logs` обслуживается параллельным обозревателем; остальные live investigation targets всё ещё требуют loader. Требования выше описывают исходное разделение задач, а не запрет на эту последующую интеграцию.
